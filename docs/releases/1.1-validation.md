## New shop fix

`shop_exit` now performs the source's documented `$BAAF` sprite-table clear
before its stage-restoration waits. Normal `build_sat` intentionally preserves
cloud/staff slots 1–6 until updated; the shop had used these same slots for goods
and cursor corners. Without clearing them, their old entries survive the shop.

`python3 tools/ss2/check_shop_exit.py` compiles the actual production function
with address/undefined-behavior sanitizers. It checks 64 initial SAT populations
at both restoration waits, plus restored camera and redraw request. Old source
fails with 16,768 stale observations; fixed source passes. This is a bounded
transition test, not a complete shop economy test.

Genesis Plus GX also reproduced the reported visual failure using the existing
NPC diagnostic loader (stage 1, NPC world 848/1616, player 820/1616), followed by
controller input through dialogue, shop browsing and END. At refresh 600 the
before/after shop captures are byte-identical. At refresh 1200 the old build
retains shop icons on the stage; the fixed build removes them. The diagnostic
warp shortens the route but the shop transition itself uses production code.
Inputs and captures are retained in `shop-before-final` / `shop-after-final`.

## Release checks

- `tools/verify_collection_release.py`: release/header version, exact ROM size,
  entry address, checksum, region/SRAM fields, source/manifest hashes, release
  copy equality, and absence of diagnostic flags pass.
- MAME Genesis: both games reach gameplay, soft reset, and reach gameplay again.
  Captures inspected. Separate inherited-I/O/stale-RAM injection restores
  initialized data twice (`DFCB0301`, at test frames 720 and 1920).
- Genesis Plus GX actual 68000 fixture: 65,536 terrain comparisons and 65,536
  signed-velocity cases pass, including RAM guards and callee-saved registers.
- Recording-VDP streamer test: 99,864,666 visible-cell comparisons pass;
  upward wrap needs 33 writes instead of 759. Detailed performance evidence is
  in the preceding [CPU](../ss2/PERFORMANCE-2026-10-26.md) and
  [scrolling](../ss2/UPWARD-SCROLL-2026-10-26.md) reports; those measurements are
  not fresh whole-game benchmarks of v1.1.
- Prior [audio fixture](../hardware/2026-10-26-boot-audio.md) tested the unchanged
  gain change across 43 requests and overlapping effects. This is historical
  component evidence, not a new physical analog-output measurement.
- Native code-generation guard passes except the existing allowed SGDK
  `Z80_upload` warnings. No new project-code hazards.

The build now gets version strings from `inc/release_version.h`, embeds the
header from the selected output directory, and writes the padded ROM's actual
end address. The old Collection header still identified a 1 MiB SonSon v1.0.

Local evidence is under `out/release-1.1/`, including build logs, release
identity, source hashes, reset captures and shop regression fixtures. The
original HuCard source and generated raw banks remain excluded from public Git
history by `tools/publish.sh`.

Physical consoles, flashcart firmware combinations and PAL remain unverified
for v1.1. Heavy-scene stutter and exact arcade/PCE parity are not claimed solved.
