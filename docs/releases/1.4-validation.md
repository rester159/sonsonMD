# Collection v1.4 — stage-one platform pacing

2026-10-28. Addresses the reported SonSon II stutter in the three-log climb
beside the trees. This is an improvement, not a sustained-60-FPS claim.

## Changes

- Cache the last composite-list lookup per object, validating the complete
  identity (list, animation address, both mapped ROM pages and part count).
- Prepack immutable pattern/attribute words and publish SAT cursor/count once
  per composite. Preserve part order, 64-entry SAT wrapping, flash palettes,
  source counters and fallback decoding across ROM-page boundaries.
- Allow the existing VInt DMA commit during input/sound preparation, after all
  presentation buffers are complete. Previously a VBlank during sound could
  miss an already-prepared picture. Preserve the SDK Z80 ownership protocol;
  mask interrupts only across sound's bus request/acknowledgement and restore
  the previous mask. DMA observes an acknowledged bus owner and leaves it held.
- Add reproducible platform-area input and a target composite-output check.

No actors, collision checks, art updates or audio events were removed. Main
checkout release is a Collection ROM; public Git remains source-only.

## Matched workload

Genesis Plus GX, NTSC 59.922743 Hz; GCC 16.1, SGDK 2.11, O3/LTO. Baseline:
local commit cd472dc with only the diagnostic input fixture added. Start stage
zero at world (1408,1712), then jump for eight ticks every 48 ticks. The player
repeatedly jumps in the pictured platform column; this is not a full ascent.
Nine objects remain active in the measured interval. Compare completed ticks
1000–6000. The six recorded state fields (camera X/Y, player X/Y, RNG and live
object count) match at 7,401 shared completed ticks. This is not a full RAM or
full-playthrough equivalence proof.

| Measure | v1.3 baseline | v1.4 candidate |
|---|---:|---:|
| Refreshes for 5,000 ticks | 5,014 | 5,013 |
| Prepared pictures | 3,095 | 3,456 |
| Prepared pictures/second | 36.99 | 41.31 |
| Worst 60-refresh prepared count | 31 | 35 |
| Longest prepared-picture gap | 4 refreshes | 3 refreshes |
| Simulation ticks/second | 59.76 | 59.77 |

These counters measure prepared presentations. An independent 240-frame video
capture (refreshes 1000–1239) contains 151 versus 167 changed images across 239
intervals, confirming an improvement in actual image delivery in that sample.
It does not establish a universal fresh-scanout floor.

A second route adds left/right movement and falls around the logs. Camera Y
ranges 1552–1747 and up to ten objects are active. Its 5,000-tick average rises
55.28→56.00 prepared pictures/second, longest gap 4→3, worst 60-refresh count
remains 29. The six recorded state fields match at 7,227 ticks. This route
spends time outside the busy column and must not replace the stationary test.

Detailed section/PC profiling identified object handling and composite SAT
construction as substantial costs. Profiling overhead reduced throughput, so
headline results above omit SS2_TPROF and PC interrupts. A speculative cell
conversion rewrite and an O2 experiment were discarded.

## Reproduction

Run from the repository root (local source ROM inputs required as usual):

```sh
python3 tools/build_native.py -D SS2_DBG_STAGE=0 -D SS2_DBG_WX=1408 \
  -D SS2_DBG_WY=1712 -D SS2_PERF_INPUT -D SS2_PERF_CLIMB \
  --out out/platform-check
python3 tools/ss2/perf/benchmark.py out/platform-check out/platform-check/run
```

Add `-D SS2_PERF_CLIMB_MOVE` for the moving/falling route. Add
`-D SS2_COMPCHECK` to that route and run
`python3 tools/ss2/perf/check_composite_output.py BUILD_DIR EVIDENCE_DIR` for
source-decoder comparison. Compare matched runs with `tools/ss2/perf/compare.py`.
Local evidence is under ignored `out/perf-platform-climb/`.

Remaining limits: busy moments still stutter; full upward traversal, PAL and
physical Models 1/2/3 have not been validated for this change. v1.4 was built
locally; this validation does not assert an itch.io upload.
